# ITtool — журнал изменений

## 3.1.0 — приложение для iPhone

- `ios/` — приложение ITtool для iPhone (SwiftUI, iOS 17): учёт техники с поиском
  и правкой карточек, недельный отчёт, выдача картриджей. Работает с той же базой,
  что терминал и бот. Иконка — своя, без логотипа; анимации,
  отклик вибрацией, сводки на каждой вкладке.
- Приложение работает без сети: база хранится в телефоне, правки копятся в очереди
  и уходят на сервер, когда он доступен; оттуда приходят правки терминала и бота
  (`GET /api/sync`). Карточки и записи, заведённые на телефоне, сервер принимает
  с их собственными id.
- Раз в неделю при открытии приложение шлёт файл с базой в телеграм-группу через
  бота отчёта; ID группы — `backup_chat` в настройках бота.
- В записи отчёта «Сотрудник / объект» подсказывает сотрудников из учёта.
- Кнопка «Отправить начальнику» на вкладке «Отчёт»: телефон сам собирает Word за
  неделю (как `reports.build_docx`) и шлёт письмо по SMTP (SSL, 465). Настройки почты —
  в настройках приложения, пароль в связке ключей; при синхронизации пустые поля
  заполняются с сервера. Клавиатура прячется кнопкой «Готово» и прокруткой.
- `api.py` — HTTP API для приложения, служба `ittool-api` (systemd --user).
  Слушает только адрес Tailscale (порт 8780), вход по токену
  (`ittool api token`). Проверки — `test_api.py`.
- `.ipa` без подписи собирает GitHub Actions (`.github/workflows/ios-ipa.yml`);
  поставить на телефон — Sideloadly или AltStore.

## 3.0.0 — ITtool в терминале на Ubuntu

- ITtool переехал с Windows на сервер Ubuntu и работает в терминале (Textual):
  `ittool` — вкладки F1 «Учёт», F2 «Отчёт», F3 «Заявки», F4 «Картриджи»,
  F5 «Настройки». Горячие клавиши работают и в русской раскладке.
- Всё, что было: дерево подразделений и карточки с техникой, поиск по любому полю,
  статистика, Excel учёта, учётки в Word, импорт MAC/IP из CSV сканера, анализ ПК
  и служебная записка, недельный отчёт и Word за неделю/месяц, отправка на почту,
  ИИ (дополнить запись, причесать, категории, выводы, месячный отчёт, заполнить
  карточку, вопрос по базе), заявки по шаблону Word, выдача картриджей и отчёт
  в Excel, резервные копии.
- Выгрузки не спрашивают, куда сохранить: кладутся в папку из настроек
  (по умолчанию `~/ITtool-выгрузки`), путь — в уведомлении.
- Телеграм-бот — отдельная служба `ittool-bot` (systemd --user); пишет в ту же базу.
  Каждая правка — одна транзакция (`db.blob_tx`), поэтому бот и открытый ITtool
  не затирают записи друг друга.
- Логика вынесена из окон в модули без интерфейса: `assets.py`, `reports.py`,
  `purchase.py`, `cartridges.py`, `settings.py`. Тесты — `test_core.py`, `test_tui.py`.
- Убрано окно Liquid Glass (Tauri), вкладки tkinter, установщик и батники Windows.
  Последняя версия для Windows — тег `windows-2.3.0`.
- База перенесена с Windows как есть: `~/.local/share/ITtool/itmanager.db`.

## 2.3.0 — дела ITtool у Моти (Coucou)

- ITtool подключается к [Coucou](https://github.com/Louis-CFM/coucou) — спутнику
  «Моти» вверху экрана. У Моти появляется своя пилюля «ittool»: пока идёт
  «подождите» (отправка отчёта, ИИ, проверка токена), Моти думает и показывает,
  что происходит; выдача картриджа, сохранение и выгрузка заявки, отчёт по
  картриджам, служебная записка, отправка письма, резервная копия — Моти
  радуется, итог в его ленте; сбой — огорчается, причина в ленте.
- Включается в «Настройки → Coucou — Моти вверху экрана», по умолчанию выключено.
- ITtool не ждёт Coucou: события уходят отдельным потоком, на соединение — 300 мс,
  Coucou не запущен — ничего не происходит. Пишем только в Coucou своего
  пользователя (`\\.\pipe\coucou-<SID>`, сервер канала проверяется). Только
  ASCII — казахские буквы доходят целыми.
- `coucou.py` — связь; тесты C1–C8 в `test_glass_forms.py` (подставной Coucou),
  проверка настроек в `glass/test_ui.js`; мутации C1–C5 и U12.

## 2.2.0 — планета из точек и новый цвет

- Фон — планета из светящихся точек, как на эскизе: материки — сеткой точек и
  рёбер, океан — редкими точками, между узлами — сеть линий с бегущими огоньками.
  Планета медленно вращается, парит, вокруг мерцают звёзды. Карта суши — Natural
  Earth 1:50m (общественное достояние), сжата в маску 240×120 прямо в `globe.js`;
  пересобрать — `glass/tools/land_mask.js`.
- Цветокор: глубокий тёмно-синий фон и бирюзовые акценты; по умолчанию тёмная тема.
  В меню «⋯ → Вид»: «Светлая тема» и «Анимации и движение фона» — выбор
  запоминается на этом компьютере.
- Панели полупрозрачные — планета видна сквозь них.
- Анимации: разделы и карточки выплывают при переключении вкладок, листы и вопросы
  мягко появляются, кнопки отвечают на нажатие, итоги в «Картриджах» докручиваются,
  только что отмеченная выдача подсвечивается в журнале.
- Бережно к компьютеру: ~30 кадров в секунду, кадр — меньше миллисекунды (точки и
  рёбра рисуются пачками); окно в трее или свёрнуто — планета стоит; «меньше
  движения» в Windows или выключенные анимации — один неподвижный кадр.
- Исправлено: основная кнопка при наведении теряла цвет.
- Тесты: 11 проверок вида и планеты в `glass/test_ui.js`, мутации U9–U11.

## 2.1.0 — учёт картриджей

Новая вкладка «Картриджи»: кто, когда, какой картридж и сколько забрал.

- Быстрая отметка: дата (сегодня), сотрудник, картридж, количество, примечание;
  Enter — записать. Сотрудник ищется в учёте по фамилии или имени («Даулет»);
  подходит несколько — программа просит выбрать, нет в списке — спрашивает,
  записать ли выдачу на это имя. Картридж, который человек брал в прошлый раз,
  подставляется сам; «ce285a» и «CE285A» — одна модель.
- Счёт: журнал выдач, сводка «По сотрудникам» и «По картриджам» — за год по
  месяцам или за один месяц; поиск по сотруднику, отделу, картриджу.
- Отчёт в Excel: листы «По сотрудникам», «По картриджам», «Журнал».
- Выдачи лежат в общей базе (таблица `cartridge_issues`) и попадают в резервные
  копии. Сотрудника переименовали — в отчётах новое ФИО; удалили из учёта — его
  выдачи остаются в счёте под именем на день выдачи.
- Программа сутками живёт в трее: наступил новый день — дата в форме снова
  «сегодня»; дата правленой записи не достаётся следующей выдаче.
- `mod_cartridges.py` — правила, сводки, Excel; `db.py` — хранение;
  `glass_api.py` — команды `cart_get`, `cart_save`, `cart_delete`, `cart_export`.
- Тесты: 36 проверок в `test_glass_forms.py`, 20 — в `glass/test_ui.js`, шаг в
  `smoke_test.py`; мутации F5–F7 (`mutate_forms.py`) и U6–U8 (`mutate_ui.js`).

## 2.0.0 — переход на Liquid Glass

Окно Tauri в стиле Liquid Glass поверх проверенной Python-логики. Решения
повторяют METROLOGY_kit 5.4 (`ServiceBridge`, `GlassForms`, якорь, батники).

### Этап 0 — инвентаризация
- Вариант «б»: формы, таблицы, отчёты. Работы с экраном нет.
- Поправка после изучения эталона: якорь 1×1 **нужен** — эталон оставляет
  системные окна выбора файла у движка (у ITtool их 11), а у скрытого окна
  tkinter их не показывает.

### Этап 1 — служебный режим и канал
- `glass_service.py`: `ServiceBridge` (канал stdin/stdout, только ASCII, stdin в
  UTF-8, поток чтения → очередь → тик `after` с флагом «занят»), `GlassForms`
  (`reply`/`invalid`/`form`, вопросы `ask`/`answer`, `busy_run`),
  `install_glass_dialogs` (все `messagebox` — в стекло), `make_anchor` и
  `make_passive` (невидимый якорь), одна копия через мьютекс.
- `main.py --service [--host <exe>]`: без заставки, трея и мастера (их возьмёт
  стекло), выход по команде окна или по концу ввода, автозапуск — через окно.
- Версия программы: `APP_VERSION = "2.0.0"`.
- `test_glass_service.py`: сквозной тест настоящего процесса с консолью cp1251
  и тест вопросов/«занято»/«подождите» на настоящем tkinter.
- `mutate_glass.py`: девять мутаций защит канала — каждая ловится тестом.

### Этап 2 — формы на стороне Python
- `glass_api.py`: данные и формы всех вкладок (F1–F16): учёт, отчёт, почта, заявки,
  настройки, мастер, служебная записка, учётки, копии, ИИ-помощник.
- Старые обработчики вызываются сами — выбор выставляется как щелчок в дереве,
  ответ формы подставляется вместо старого окна ввода. Тела, сшитые с окнами
  (письмо, ИИ-помощник, служебная записка), перенесены построчно.
- Из учёта вынесены без изменения поведения: текст статистики (`stats_text`)
  и промпт заполнения карточки (`AI_FILL_PROMPT`).
- Запрос формы, пришедший пока движок ждёт ответа, получает отказ «Подождите —
  программа занята» — форма показывает его и остаётся открытой.
- `test_glass_forms.py`: 50 проверок на настоящем ITtool в служебном режиме.

### Этап 3 — оболочка Tauri
- Rust-оболочка эталона без переключения на классический интерфейс: движок как
  ресурс, `CREATE_NO_WINDOW`, `--service --host`, поток чтения → `emit("engine")`,
  `AllowSetForegroundWindow` при каждой команде, трей, одна копия, крестик — в трей,
  `--tray` для автозапуска, плашка при сбое движка.
- Хук установщика: сначала окно, пауза, затем движок.

### Этап 4 — интерфейс
- `glass/ui`: заставка с живым логотипом, свой стеклянный заголовок, вкладки
  с линзой на пружинах, учёт (дерево и карточка), отчёт, заявки, листы форм,
  вопросы, «подождите», демонстрация без Tauri. «Меньше движения» — логотип
  неподвижен, пружины без анимации; «без прозрачности» — плотные панели.
- `glass/test_ui.js`: 39 проверок в jsdom.

### Этап 5 — живой прогон
- Отладочная сборка окна под Xvfb, openbox и D-Bus, настоящий движок ITtool
  через `ITTOOL_ENGINE`, щелчки `xdotool` по координатам со снимков.
- Проверено: окно в стекле с данными базы, ни одного окна tkinter (только якорь
  1×1, менеджер окон его не растянул); карточка, отчёт, заявки и вопрос
  «Удалить сотрудника…» — в стекле, «Нет» не удаляет; перетаскивание за шапку,
  «развернуть», крестик прячет в трей при живом движке, повторный запуск
  показывает уже работающую копию; падение движка → плашка → «Перезапустить».
- Исправлено по прогону: имя класса ряда кнопок совпадало с полоской прогресса
  эталона (`.bar` → `.btnrow`); компактные кнопки в левой панели; у устройства
  заголовок в единственном числе («ПК»); значки окна в RGBA.

### Этап 6 — батники
- `fix_setup.bat` и `build_all.bat` по образцу эталона: удержание от сна,
  предупреждение о батарее, поиск инструментов по известным путям, тесты перед
  сборкой, одна версия во всех местах (`check_version.py`), установщик в `release`.
- `lint_bat.py`: проверка батников.

### Исправления после первой сборки на Windows
- Движок сообщает причину сбоя при запуске событием `fatal` — окно показывает её
  на плашке, тест — в журнале вместе с выводом ошибок движка.
- stdout движка зарезервирован под канал: случайный `print` уходит в stderr и не
  может ни сломать канал, ни уронить движок на кириллице при консоли cp1251.
- Тесты изолированы от настоящих данных: временные `APPDATA` и `LOCALAPPDATA`,
  без импорта старых данных (`ITTOOL_NO_LEGACY`), своя метка одного экземпляра
  (`ITTOOL_SINGLE_MUTEX`) — не сталкиваются с запущенным ITtool.
- Новые проверки канала: случайный print при запуске, сбой при запуске, вторая
  копия (Windows). Мутации M10, M11 ловятся.
- `build_all.bat` перед тестами убирает зависшие движки от прошлых запусков.
- Найдена причина сбоя на Windows: тест подменял `APPDATA`, а из неё Python
  вычисляет папку пользовательских пакетов — движок в тесте терял `python-docx`.
  Тест передаёт `PYTHONUSERBASE`; проверка A0 называет такую проблему прямо.
