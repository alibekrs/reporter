# ITtool — заметки для работы с кодом

Программа системного администратора: учёт сотрудников и техники, недельный отчёт,
заявки на закуп, выдача картриджей. Работает в терминале на сервере Ubuntu
(Textual). Интерфейс и все тексты — на русском; в данных бывают казахские буквы
(Ә, Ұ, Қ…) — их нельзя терять.

## Устройство
- `ittool` — запуск (сам создаёт `.venv`); `ittool bot` — служба телеграм-бота.
- Интерфейс: `ittool.py` (приложение, вкладки F1–F5), `tui_assets.py` (учёт),
  `tui_reports.py` (отчёт), `tui_office.py` (заявки, картриджи, настройки),
  `tui_common.py` (окна: вопрос, ввод, текст, месяц, основа форм; `keys()` —
  горячая клавиша плюс её двойник в русской раскладке; `guard` — отказ ValueError
  уведомлением; `busy` — долгое дело в потоке).
- Логика без интерфейса: `assets.py`, `reports.py`, `purchase.py`, `cartridges.py`,
  `settings.py`; Word/Excel — там же и в `docx_export.py`, `uchetki_export.py`,
  `pc_audit.py`. Интерфейс только показывает и зовёт эти функции.
- `db.py` — SQLite в `~/.local/share/ITtool/itmanager.db` (`$APPDATA`, если задан).
  Учёт и отчёт — JSON-блобы; заявки и картриджи — таблицы. Менять блоб — только
  через `db.blob_tx` (`assets.assets_tx()`, `reports.report_tx()`): свежие данные
  под блокировкой записи. Интерфейс и бот — разные процессы; не держать данные
  в памяти и не записывать их целиком «потом».
- Выгрузки — `settings.export_path(имя)`: папка из настроек, по умолчанию
  `~/ITtool-выгрузки`, без перезаписи (`имя (2).docx`).
- `tg_bot.py` + `bot_service.py` — бот; мост к отчёту — `reports.BotBridge`.
  Служба: `deploy/ittool-bot.service`, ставит `deploy/install.sh`.
- `api.py` — HTTP API (JSON) для приложения на iPhone (`ios/`): `ittool api`,
  служба `deploy/ittool-api.service`. Слушает свой адрес в Tailscale (`tailscale ip -4`), порт 8780,
  вход — `Authorization: Bearer <токен>`, токен — `api_token` в папке данных
  (`ittool api token`). Только зовёт функции логики; отказ ValueError → 400.
  Приложение для iPhone (REPORTER, `ios/`) с сервером больше не связано: работает без сети,
  данные лежат в телефоне, копия — бэкап в Telegram; к `api.py` оно не обращается.
  Правила записи в `ios/App/Store.swift` повторяют модули логики, но уже расходятся с ними:
  в телефоне выдача картриджа сама пишет заявку в отчёт, сервер и бот так не делают.
- `scan_net.ps1`, `collect_mac.ps1` — запускаются на Windows-компьютерах офиса,
  их CSV импортируется в учёт (i на вкладке «Учёт»).

## Проверки (все должны быть зелёными)
- `.venv/bin/python test_core.py` — ядро: учёт, отчёт, заявки, картриджи,
  настройки, параллельная запись из двух процессов.
- `.venv/bin/python test_api.py` — API: токен, учёт, отчёт, заявки, картриджи.
- `.venv/bin/python test_tui.py` — интерфейс: клавиши и формы через Textual pilot.
- Тесты берут временную папку данных (`APPDATA`, `ITTOOL_NO_LEGACY`) и не трогают
  настоящую базу.
- iOS (`ios/`): CI `.github/workflows/ios-ipa.yml`, задача `ui` — проход по приложению
  в симуляторе iPhone 15 Pro Max (`ios/UITests/TourTests.swift`): вкладки, «+», заведение
  данных, свайпы, клавиатура, длинный список. На каждый push — iOS 27.2 (как на телефоне);
  iOS 26.5 — только вручную (Run workflow, галочка ios26), минуты macOS идут ×10.
  Скриншоты и лист кадров заставки — артефакты `screens-ios27` (`screens-ios26`).
  IPA отдавать, только когда проверка зелёная и скриншоты просмотрены.

## Правила
- Исходники — LF.
- Версия — `APP_VERSION` в `ittool.py` и раздел в `CHANGELOG.md`.
- sudo на сервере нет: всё ставится в `.venv` и `~/.local`, службы — `systemctl --user`.
- Новая операция: функция в модуле логики (отказ — ValueError с готовым текстом),
  проверка в `test_core.py`; во вкладке — обработчик с `@guard`, долгое — через `busy`.
